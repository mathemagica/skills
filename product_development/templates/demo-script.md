# Prototype Demo Script (Template)

A short script the vision owner can use to show the prototype to potential
users, partners or funders. Write it after verification, using only behavior that
was actually checked. Keep it to about five minutes.

This is an explanatory demo, not an uncoached usability test. If the goal is to
observe whether users can discover the workflow themselves, give them the task
before demonstrating its solution. Simulated steps cannot establish real delivery
or response rates.

- What's simulated: [mocked data, integrations or steps]. Say this out loud.
- How to open it: [startup instructions or link, if sharing was authorized].

## The walkthrough

1. **Set the scene (30 seconds).** "Here's the problem: [one sentence]. Today
   people [current workaround]."
2. **Show the main workflow (2-3 minutes).** [Step-by-step actions, with the
   synthetic example data to use at each step.]
3. **Show one thing going wrong (30 seconds).** [A verified error or recovery
   path, which shows the product handles real situations.]
4. **Say what it doesn't do yet (30 seconds).** [Key exclusions.]

## Questions to ask, not just answer

- "When did you last run into this problem? What did you do?"
- "What would you expect to happen next here?"
- "What would stop you from using something like this?"

Avoid "Do you like it?" Positive reactions are encouragement, not evidence of
demand. Note what people do and say, and use
[product-market-testing](../product-market-testing/SKILL.md) for structured tests.

## Don't

- Don't promise features, dates or prices that weren't agreed.
- Don't use real personal or sensitive data in a demo without readiness work.
- Don't share a link or download publicly without the owner's authorization.
